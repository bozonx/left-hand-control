# Сквозной аудит, 2026-11-02

Проверено текущее рабочее дерево, включая незакоммиченные изменения. Исходники
приложения не менялись. Это статический аудит; сценарии ниже выведены из кода,
не воспроизведены в графической сессии.

## 1. P1 — обновление конфигурации нарушает порядок выполнения команд

`crates/lhc-core/src/mapper/linux/mod.rs:82–84`: новое сообщение `Config`
удаляет **все** предыдущие `Config` из очереди, включая сообщения перед `Execute`.
Обработчик на строках 686–715 выполняет оставшуюся очередь последовательно.

Сценарий: движок использует C0; shell отправляет C1 с изменённым макросом,
затем `Execute(macro:x)`, затем C2. Если mapper ещё не забрал пакет, очередь
`[Config(C1), Execute(x)]` превращается в `[Execute(x), Config(C2)]`.
Макрос исполняется по C0. При изменении команды это может запустить старый
скрипт; новая команда может вообще отсутствовать в C0.

Исправление: объединять только обновления после последнего барьера выполнения
либо связывать выполнение с конкретной ревизией конфигурации. Регрессионный
тест должен проверять именно `Config → Execute → Config`, а не только
несколько последовательных обновлений.

## 2. P1 — после неудачного переключения меню и mapper используют разные раскладки

`apps/slint-shell/src/document.rs:269–300` намеренно сохраняет предыдущую
конфигурацию mapper при ошибке переключения контекста. Но
`apps/slint-shell/src/app/popups.rs:60–68` загружает меню через
`active_layout(current_context)`, а не через успешно переданную раскладку.
`sync_worker_menus` на строках 136–151 делает то же для Spell.

Сценарий: A работает; автоматическое правило выбирает B; B содержит блокирующую
ошибку правил, но корректные меню. `runtime_config()` отклоняет B, mapper
остаётся на A, а popup показывает B. Выбор `macro:x` или `cmd:x` передаёт только
строку действия в работающий mapper (`popups.rs:315–340`, `app/mod.rs`, ветка
`ShellCommand::Execute`). Определение берётся из A: действие либо пропадает,
либо выполняет другое содержимое при совпадении ID.

Исправление: при работающем mapper выбирать меню из согласованного снимка его
конфигурации/раскладки. Отдельно определить поведение меню при остановленном
mapper. Проверять ошибочное переключение и одинаковые ID с разными действиями.

## 3. P2 — сбор заголовков окон остаётся включённым после удаления потребности

Единственные вызовы `active_window::set_titles_needed` в shell находятся в
`app/mapper.rs:475` (запуск) и `document.rs:287` (синхронизация работающего
mapper). При остановленном mapper `sync_runtime` выходит на строке 278,
не обновляя флаг. Остановка и аварийное завершение тоже его не сбрасывают.

Сценарий: запустить раскладку с `title:`-условием, остановить mapper, удалить
условие или переключиться на раскладку без него. `TITLES_FOR_SHELL` остаётся
true, и watcher продолжает запрашивать и хранить заголовки окон до следующего
успешного обновления работающего mapper или перезапуска приложения. Это
лишний сбор приватных данных и работа интеграции KWin.

Исправление: вычислять потребность отдельно от успешной сборки/запуска mapper,
учитывая актуальные потребности shell и автоусловий. Game-mode имеет отдельный
флаг, его при этом сбрасывать нельзя.

## 4. P2 — перегрузка событий ограничена только для состояний

`crates/lhc-core/src/events.rs:200–205` объединяет события состояния, но
безусловно добавляет запросы и результаты в неограниченный `VecDeque`.
`apps/slint-shell/src/app/mapper.rs:38–51` ждёт обработки каждого события UI
перед следующим. Это ограничивает очередь Slint, но переносит накопление в
EventBus.

При длительном замедлении UI поток `AppAction`, `ActionUnavailable` и ошибок
макросов может накапливаться без предела. После восстановления UI выполняет
устаревшие запросы, в том числе переключения раскладок/mapper; при устойчивой
перегрузке растёт память. Это архитектурный риск, нагрузочное воспроизведение
не проводилось.

Исправление: задать пределы и политику перегрузки отдельно для действий и
диагностики; повторяющиеся ошибки объединять, устаревшие запросы привязывать
к поколению mapper. Не блокировать поток перехвата клавиатуры.

# Проверка Slint-прототипа на Windows

Статус: подготовка стенда.

Воспроизводимая настройка KVM/QEMU, Windows, toolchain, передача файлов и разбор известных проблем описаны в [руководстве по Windows-тестированию](../docs/windows-testing.md).

Цель — проверить Windows-часть платформенного пилота Slint до решения о полном переносе UI. Полноценный keymapper, системные раскладки, слои и макросы в эту проверку не входят: Windows mapper основного приложения пока не реализован и проверяется позднее по [отдельному продуктовому плану](cross-platform-product-validation-plan.md).

## 1. Стенд

- Windows 11 Enterprise Evaluation 25H2 x64.
- KVM/QEMU с UEFI, TPM 2.0 и отдельным qcow2-диском.
- 4 vCPU, 6 ГиБ RAM, диск 64 ГиБ.
- Один монитор 1920×1080, масштаб Windows 100%; затем 125% и 150%.
- Системные языки ввода English (US) и Russian.
- Приложения-получатели: Notepad, Windows Terminal и браузер.
- Release-сборка `prototypes/slint-shell` без Linux-only feature `spell`.

Зафиксировать версию Windows, commit, Rust, Slint, renderer и режим масштабирования. Производительность VM не сравнивать напрямую с физическим KDE-стендом.

## 2. Подготовка

- [ ] Установить Windows и все обновления, необходимые для воспроизводимого стенда.
- [ ] Создать snapshot `windows-clean` до установки toolchain.
- [ ] Установить Git и Rust stable MSVC, клонировать или скопировать репозиторий.
- [ ] Выполнить `cargo test --locked --manifest-path prototypes/slint-shell/Cargo.toml --bin slint-shell`.
- [ ] Выполнить `cargo build --release --locked --manifest-path prototypes/slint-shell/Cargo.toml --bin slint-shell`.
- [ ] Создать snapshot `slint-ready`.
- [ ] Убедиться, что TCP-порт `127.0.0.1:43176` свободен; тест не должен слушать внешний интерфейс.

## 3. Запуск и базовый lifecycle

- [ ] Запустить release-бинарник без консольных panic/error.
- [ ] Настройки изначально скрыты, процесс доступен через tray.
- [ ] Повторный запуск CLI обращается к существующему процессу, а не создаёт второй UI-сервер.
- [ ] `show settings`, `show emoji`, `show quick`, `hide`, `toggle-mapper`, `quit` работают через loopback IPC.
- [ ] После `quit` процесс и listener завершаются; следующий запуск успешен.
- [ ] Некорректный `SLINT_SHELL_POPUPS=spell` завершается с понятной ошибкой; `auto` и `winit` используют переносимые окна.
- [ ] Завершение процесса с открытым и скрытым окном не оставляет tray icon или listener.

## 4. Настройки и редактор

- [ ] Клавиатура примерно из 80 клавиш отображается без обрезания.
- [ ] Выделение, hover и открытие редактора выбранной клавиши работают мышью и клавиатурой.
- [ ] Категории действий, поиск и каталог из 500 записей работают без заметных зависаний.
- [ ] Текстовое, числовое, select- и hotkey-поля принимают ввод.
- [ ] Валидация, disabled-состояния, Save и Cancel работают; Cancel не изменяет сохранённое значение.
- [ ] Tab/Shift+Tab, Enter и Esc имеют правильную семантику.
- [ ] Кириллица, выделение, копирование и вставка работают в формах.
- [ ] Модалка возвращает фокус вызывающему элементу.
- [ ] Dropdown возле края окна остаётся видимым.
- [ ] DnD показывает место вставки, прокручивает край и сохраняет новый порядок.
- [ ] Страница с 1500 emoji прокручивается и остаётся управляемой.

## 5. Тема, локализация и DPI

- [ ] Dark/light переключаются без пересоздания окна.
- [ ] Системная тема применяется после изменения Windows theme.
- [ ] ru/en переключаются на лету в настройках и обоих попапах.
- [ ] Длинные русские подписи не обрезают критические controls.
- [ ] При 100%, 125% и 150% проверены текст, иконки, click areas, dropdown, modal и scrolling.
- [ ] После изменения DPI и переноса между мониторами геометрия и области клика совпадают с отрисовкой.

## 6. Tray и способы вызова

- [ ] Tray icon виден, tooltip корректен, меню открывается правой кнопкой.
- [ ] Пункты Settings, Emoji, Quick, Mapper и Quit выполняют правильные действия.
- [ ] Toggle mapper меняет состояние без падения и зависания меню.
- [ ] Левый клик ведёт себя согласно выбранному контракту и не создаёт дубликат окна.
- [ ] F13 открывает Emoji, ScrollLock — Quick через `global-hotkey`.
- [ ] Хоткеи работают, когда активны Notepad, Windows Terminal и браузер.
- [ ] Занятый другой программой хоткей даёт видимую диагностическую ошибку.
- [ ] `SLINT_SHELL_HOTKEYS=off` действительно отключает регистрацию.
- [ ] Вызов из настроек, tray, hotkey и IPC проверен хотя бы один раз для каждого попапа.

## 7. Попапы, фокус и геометрия

- [ ] Emoji и Quick открываются поверх исходного приложения.
- [ ] Первое нажатие стрелки обрабатывает попап без предварительного клика.
- [ ] Enter выбирает элемент, Esc закрывает без вставки.
- [ ] Потеря фокуса скрывает попап.
- [ ] Попап не появляется как отдельная постоянная кнопка taskbar.
- [ ] Повторное открытие не создаёт дубликаты окон и не оставляет невидимый focus trap.
- [ ] Попап размещается снизу по центру доступной рабочей области с отступом 24 логических px.
- [ ] Taskbar сверху, снизу, слева и auto-hide не перекрывает критическое содержимое.
- [ ] Maximized и fullscreen исходные окна проверены отдельно.
- [ ] На втором мониторе попап появляется на ожидаемом display и остаётся видимым после отключения этого display.
- [ ] Цветные emoji, прозрачность, скругления и отсутствие обрезания подтверждены скриншотами.

## 8. Возврат фокуса и текста

Для Emoji и Quick выполнить по пять полных циклов в Notepad, Windows Terminal и браузере:

1. Сфокусировать поле и запомнить положение caret.
2. Открыть попап глобальным хоткеем.
3. Выполнить поиск или навигацию первой клавишей.
4. Выбрать элемент Enter.
5. Проверить скрытие попапа, возврат исходного foreground window и единственную вставку.

- [ ] Латиница, кириллица и emoji вводятся полностью и ровно один раз.
- [ ] Ввод происходит в исходное окно, если пользователь не менял приложение.
- [ ] Если пользователь успел переключить приложение, текст не попадает в постороннее окно.
- [ ] Esc и потеря фокуса не вводят текст.
- [ ] Зажатый до открытия Shift/Ctrl/Alt/Win после закрытия не остаётся логически зажатым.
- [ ] Ошибка `SetForegroundWindow` или `enigo` записывается в лог и не приводит к вводу в неверное окно.

Итог для каждого попапа записать как успешные/все попытки по каждому приложению. Любой неверный адресат, дубликат или потеря текста требует исправления и повтора затронутой серии.

## 9. Минимальные метрики и устойчивость

- [ ] Записать первый и пять повторных вызовов каждого попапа через hotkey и IPC.
- [ ] Отдельно записать наличие `t3`, `t4`, `t5` и пропуски; возврат из `show` не считать готовым кадром.
- [ ] Измерить private bytes и working set: старт, после прогрева/скрытия, оба попапа, редактор с 500 записями.
- [ ] Проверить CPU в прогретом простое со скрытыми окнами.
- [ ] Выполнить 100 циклов show/hide каждого попапа без роста числа окон, потери tray и зависания.
- [ ] Проверить lock/unlock и sleep/wake VM.

## 10. Критерий результата

Windows считается пройденной для решения по Slint, если:

- release-сборка и тесты успешны;
- настройки, tray, оба попапа, hotkey и IPC работают;
- формы, DnD, ru/en, dark/light и 100/125/150% не имеют блокирующих дефектов;
- по 15 из 15 циклов возврата ввода успешны для каждого попапа;
- Esc и потеря фокуса не вставляют текст;
- нет залипших модификаторов, неверного адресата, дубликатов окон и постоянной фоновой нагрузки;
- ограничения VM и все найденные обходы записаны в `slint-prototype-report.md`.

Успех этого плана подтверждает Windows-архитектуру Slint shell, но не поддержку полноценного Windows keymapper.

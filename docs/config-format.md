# Формат config.json и файлов раскладок

Приложение хранит два вида файлов:

- `config.json` — настройки этого компьютера и состояние приложения;
- `layouts/<имя>.json` — раскладки библиотеки. Раскладка переносима: её можно скопировать на другой компьютер.

Пути к каталогам описаны в [руководстве разработчика](development/guide.md). Оба файла редактируются только через приложение. Ручное редактирование не поддерживается: оно делается на страх и риск пользователя. Такие изменения в лучшем случае применяются после перезапуска и могут быть перезаписаны следующим сохранением, а ошибка в файле не даёт приложению загрузить его.

## Общие правила

- Каждый файл содержит `"schemaVersion": 1` — версию схемы своего формата. Версии `config.json` и раскладок независимы; сейчас обе равны 1. Файл без версии не загружается. Если версия больше поддерживаемой, приложение сообщает, что файл создан более новой версией, и не загружает его.
- Чтение строгое: неизвестное поле, значение не того типа или неизвестное значение перечисления — ошибка с номером строки и столбца. Файл при этом не перезаписывается. Так приложение никогда не сохраняет файл, молча выбросив непонятые части.
- Необязательные поля можно не писать: берётся значение по умолчанию. Приложение не записывает пустые списки и значения по умолчанию. В `config.json` записываются только настройки, отличающиеся от значений по умолчанию, поэтому новая версия может изменить значение по умолчанию для всех, кто его не менял.
- Стиль имён: поля — camelCase; значения перечислений — camelCase (`permissiveHold`, `libeiPure`, `eInk`); сочетания клавиш — синтаксис действий (`Ctrl+Shift+KeyV`); языки — коды BCP 47 (`ru`, `zh-Hans`).
- Смысловые проблемы (ссылка на несуществующий макрос, неизвестная клавиша в действии) не мешают загрузке. Их показывает диагностика правил, а mapper не запускается с блокирующими ошибками.
- Политика совместимости. В версии 1 могут появляться только новые необязательные поля и новые значения перечислений; смысл существующих полей не меняется. Любое другое изменение повышает `schemaVersion`. Старая сборка не читает файл с полем или значением, которого она не знает: в ошибке она указывает, что файл, вероятно, создан более новой версией приложения, и не перезаписывает его. Раскладка, сохранённая новой версией, может не открыться в старой, если в ней используются новые возможности.
- Повышение версии. Когда версия формата повышается, новая сборка по-прежнему читает файлы прежних версий и переводит их в текущую. Приложение всегда записывает текущую версию; перед первой перезаписью файла прежней версии рядом сохраняется его копия `<файл>.v<версия>.bak` (например, `config.json.v1.bak`), а существующая копия не заменяется. Форматы, существовавшие до `schemaVersion`, не поддерживаются.

### Подсказки редактора и терминология

Оба формата принимают необязательное корневое поле `$schema` — строку с адресом
JSON Schema для редактора. Приложение сохраняет её при редактировании, но не
загружает схему из сети и не использует адрес для выбора формата: это определяет
только `schemaVersion`. При отсутствии поля приложение его не добавляет;
`null` и значения других типов запрещены.

`layouts` в настройках означает раскладки приложения (библиотеку).
`when.keyboardLayouts` и `sys:switchLayoutN` относятся к системной раскладке
клавиатуры.

### Идентификаторы

`id` уникален внутри своей коллекции: слои, правила, макросы, команды, страницы
быстрых действий, страницы эмодзи, автоправила и процессы игрового режима.
Сравнение ID регистрозависимое. Разные коллекции могут использовать одинаковый `id`.
У всех этих ID одна грамматика: от 1 до 64 символов из латинских букв, цифр, `_` и `-`
(`[A-Za-z0-9_-]{1,64}`). Поэтому ID без экранирования стоят в строках действий
(`macro:<id>`, `cmd:<id>`). Дубликаты — ошибка загрузки, а не правило
«последний побеждает». У шагов макроса ID нет: в JSON шаги — просто строки.

ID раскладок библиотеки устроены иначе: `user:<имя файла без .json>`. Имя файла
задаёт пользователь, поэтому оно может содержать любые символы, допустимые в
имени файла (`user:Основная`). Префикс `user:` оставляет место для других
источников раскладок.

У правил, страниц, автоправил и процессов можно пропустить `id`: загрузчик
детерминированно создаёт его (`rule-1`, `page-1`, `emoji-1`, `process-1`),
предварительно резервируя все явно заданные ID этой коллекции. При сохранении
созданные ID записываются в файл.

### Условия `when`

Правила раскладки и автоправила (`settings.layouts.auto.rules`) используют один объект условий:

| Поле | Смысл |
| --- | --- |
| `gameMode` | `on` или `off` — состояние игрового режима |
| `keyboardLayouts` | короткие id системной раскладки клавиатуры, например `us`; подходит любая из списка |
| `windows` | шаблоны активного окна; подходит любой из списка |
| `excludeWindows` | шаблоны окон, при которых условие не выполняется; если активное окно определить нельзя, условие тоже не выполняется |

Должны выполняться все заданные условия; объект без условий подходит всегда.
Шаблон окна — id приложения или имя процесса целиком без учёта регистра (`org.telegram.desktop`,
`Game.exe`, `.exe` необязательно), с масками `*` и `?` (`steam_app_*`), либо
`title:<текст>` — заголовок окна содержит текст.

### Контракт таймингов

Все длительности — целые миллисекунды. Дробные, отрицательные и выходящие за
диапазон числовые поля отклоняются при загрузке и редактировании; молчаливого
ограничения значений сохранённого файла нет. Некорректное действие `pause:`
в загруженном макросе показывает смысловая диагностика; mapper с ним не запускается.

| Поля | Допустимый диапазон, мс |
| --- | --- |
| `settings.timing.holdMs`, `doubleTapMs`; `rules[].hold.timeoutMs`, `doubleTap.timeoutMs` | 50–1000 |
| `settings.timing.longHoldMs`; `rules[].longHold.timeoutMs` | 100–60000 |
| `settings.timing.comboMs` | 10–500 |
| `settings.timing.macroStepPauseMs`, `macroModifierDelayMs`; `macros[].stepPauseMs`, `modifierDelayMs` | 0–2000 |
| `pause:<мс>` в шагах макроса | 1–10000 |
| `settings.timing.macroTimeoutMs` | 1000–600000 |

Отсутствующий тайминг правила или макроса наследует соответствующую настройку
из `settings.timing`; при сохранении наследуемое поле опускается. Явный `null`
в таймингах запрещён везде. В действиях `null` по-прежнему означает «ничего не делать».
Ноль разрешён только для межшаговой задержки и задержки модификаторов: он
означает отсутствие дополнительной задержки. Ноль не означает наследование,
отключение распознавания жеста или неограниченное выполнение макроса.
`macroTimeoutMs` ограничивает выполнение макроса целиком; отдельная допустимая
пауза не отменяет этот предел. Hold и long hold — альтернативные режимы,
поэтому требования `longHoldMs > holdMs` нет.

### Диагностика содержимого

Перед запуском mapper проверяется вся активная раскладка: действия правил,
клавиши и действия слоёв, шаги и циклы вызовов макросов, действия быстрых меню,
условия окон и поддерживаемые сочетания параметров правил. Ошибка содержит
путь к элементу; для макроса указывается конкретный шаг. Некорректное действие
в слое или меню не пропускается молча. Диагностика не переписывает файл:
раскладку со смысловыми ошибками можно открыть и исправить в редакторе.


## Действия

Действие — строка:

| Вид | Пример |
| --- | --- |
| клавиша или сочетание (коды W3C `KeyboardEvent.code`) | `KeyA`, `Ctrl+KeyC`, `Ctrl+Shift+ArrowLeft` |
| пользовательский макрос | `macro:myMacro` |
| встроенный макрос | `builtin:copyLineText` |
| команда | `cmd:<id>` |
| системное действие | `sys:switchDesktop2`, `sys:showDesktop` |
| действие приложения | `app:showQuickMenu1`, `app:gameModeToggle` |
| глобальное сочетание KDE | `kde:kwin/Window Maximize` |
| ввод текста | `text:Привет` |
| пауза (только в макросах) | `pause:200` |

Строка вида `слово:…` с неизвестным префиксом из строчной латинской буквы и букв или цифр (например, действие из более новой версии) загружается и сохраняется без изменений, но диагностика сообщает о неизвестном типе действия, и mapper с ним не запускается.

Там, где действие необязательно, отсутствие поля значит «как у физической клавиши», а `null` — «ничего не делать». Пустая строка — ошибка.

Сочетание в действии записывается как модификаторы и основная клавиша через `+`: `Ctrl`, `Shift`, `Alt`, `Meta` обозначают левую клавишу модификатора, а коды с указанием стороны (`ControlRight`, `AltRight`) — конкретную. Каноническая форма — `Ctrl+Shift+KeyA`: сначала модификаторы, без пробелов. Клавиша правила (`rules[].key`) хранится только кодами клавиш: при загрузке `Ctrl+KeyA` записывается как `ControlLeft+KeyA`.

Встроенные макросы используют ссылки `builtin:<id>`, пользовательские — `macro:<id>`. Их ID могут совпадать: ссылки разрешаются независимо.

Действия `app:showQuickMenuN` и `app:showEmojiMenuN` открывают страницу меню по её позиции (N от 1, без верхней границы; если страницы с таким номером нет, открывается последняя). `app:activateLayoutN` (N от 1 до 5) включает раскладку по позиции в порядке библиотеки (`settings.layouts.order`). Ссылка по позиции, а не по id, выбрана намеренно: клавиши назначаются на номера один раз, а что они открывают, меняется перестановкой страниц или раскладок, которую видно в интерфейсе. Перестановка и удаление страниц в редакторе эти действия не переписывают.

## config.json

Пример со всеми полями (приложение записывает только отличия от значений по умолчанию):

```json

  "settings": {
    "experimental": false,
    "launchOnStartup": false,
    "startMapperOnLaunch": true,
    "appearance": "system",
    "highContrast": false,
    "reduceMotion": false,
    "layoutOsd": false,
    "layerHint": false,
    "locale": "auto",
    "devices": {
      "keyboards": ["/dev/input/by-id/usb-Keyboard-event-kbd"],
      "mice": ["/dev/input/by-id/usb-Mouse-event-mouse"]
    },
    "timing": {
      "holdMs": 200,
      "longHoldMs": 1000,
      "doubleTapMs": 200,
      "comboMs": 50,
```

### settings

| Поле | Значения | По умолчанию |
| --- | --- | --- |
| `experimental` | показывать в интерфейсе возможности, которые ещё в разработке (сейчас — управление игровым режимом); поведение ядра не меняется | `false` |
| `appearance` | `system`, `light`, `dark`, `eInk` | `system` |
| `locale` | `auto`, `en`, `ru`, `de`, `fr`, `es`, `it`, `pt`, `pl`, `tr`, `uk`, `cs`, `hu`, `ro`, `el`, `hr`, `ka`, `kk`, `zh-Hans`, `zh-Hant`, `ja`, `ko` | `auto` |
| `devices.keyboards`, `devices.mice` | списки путей к устройствам ввода; в Linux — стабильная ссылка `/dev/input/by-id/…` или `/dev/input/by-path/…`, которая переживает перезагрузку и переподключение. Формат допускает несколько устройств, текущая версия поддерживает не больше одного устройства каждого вида; больший список — ошибка загрузки | пусто |
| `timing` | значения по умолчанию для правил и макросов, в миллисекундах; правило или макрос может задать своё | см. пример |
| `timing.tapDecision` | `permissiveHold` (нажатие другой клавиши фиксирует удержание только при вложенном отпускании или по таймауту), `holdOnOtherKeyPress` (сразу) | `permissiveHold` |
| `layouts.mode` | `manual` — работает `layouts.manual`; `auto` — первое подходящее правило `layouts.auto.rules`, иначе `layouts.auto.fallback` | `manual` |
| `layouts.manual` | id раскладки ручного режима | нет |
| `layouts.order` | порядок раскладок библиотеки (id); задаёт номера для `app:activateLayoutN` и порядок списка. Раскладки, которых нет в списке, идут после перечисленных | пусто |
| `layouts.auto.rules[].layoutId` | обязательно: id раскладки или явный `null` (нативный ввод без переназначений). Пустая строка — ошибка | — |
| `layouts.auto.rules[].enabled` | `false` сохраняет правило, но не применяет его | `true` |
| `layouts.auto.rules[].when` | [условия](#условия-when); правила проверяются по порядку, применяется первое подходящее | — |
| `layouts.auto.fallback` | раскладка, когда ни одно правило не подошло; `null` — нативный ввод | `null` |
| `commandsEnabled` | разрешить действия `cmd:`; без этого команды из раскладок не выполняются | `false` |
| `gameMode.detectors` | источники автоопределения игр; каждая платформа использует только свои | зависит от ОС |
| `gameMode.foregroundOnly` | игры из `detectors` (лаунчеры, Game Bar) учитываются, только пока их окно активно; Steam в Windows не называет процесс игры и учитывается всегда | `true` |
| `gameMode.processes[]` | процесс-признак игры: `name` — шаблон процесса, `onlyActiveWindow` (по умолчанию `true`) — учитывать процесс, только пока его окно активно; с `"exclude": true` — процесс, который игровой режим не включает | — |
| `linux.textMode` | `libei`, `libeiPure`, `keycode`, `clipboard`, `ydotool`, `xdotool` | `libei` |
| `linux.pasteShortcut` | сочетание вставки в синтаксисе действий. Порядок и написание модификаторов не важны (`Shift+Ctrl+KeyV` = `Ctrl+Shift+KeyV`). Текущая версия поддерживает `Shift+Insert`, `Ctrl+KeyV`, `Ctrl+Shift+KeyV`; другое сочетание — ошибка загрузки | `Shift+Insert` |
| `linux.terminalPasteShortcut` | сочетание вставки, когда получатель — терминал (Konsole, kitty, Alacritty, GNOME Terminal и др., определяется по классу окна); те же значения или `null` — как `pasteShortcut` | `Ctrl+Shift+KeyV` |
| `linux.ydotoolPath`, `linux.xdotoolPath` | путь к программе; пусто — поиск в `PATH` | пусто |

Id раскладок библиотеки имеют вид `user:<имя файла без .json>`. При переименовании раскладки в приложении все ссылки в `config.json` обновляются.

### state

Состояние, которое приложение запоминает само: раскладка, открытая в редакторе (`editedLayoutId`), и положение переключателя игрового режима (`gameModeSwitch`: `auto`, `on`, `off`).

## Файл раскладки

Необязательный объект `meta` содержит необязательные строки `name`, `author`,
`version` и `description`. `name` — переносимое авторское название, независимое
от имени файла; `author` — автор; `version` — произвольная строка авторской
версии раскладки, не связанная с `schemaVersion`; `description` — описание,
которое показывает и редактирует библиотека. Неизвестные поля, `null` и значения
других типов запрещены. Метаданные сохраняются при редактировании, копировании и
переименовании.

Имя файла остаётся локальным именем в библиотеке и основой ID `user:<имя>`.
Переименование файла или локальной копии не меняет авторское `meta.name`.
Метаданные не задают стабильный ID и не используются для поиска обновлений.
Редактор пока не предоставляет полей для изменения `meta.name`, `meta.author` и `meta.version`.

### Слои

`id` обязателен, `name` по умолчанию равен `id` (совпадающее с `id` имя не записывается; так же у макросов и команд). В `keys` код клавиши указывает на действие; `null` глушит клавишу в слое, а клавиша, которой нет в `keys`, прозрачна (работает правило базового слоя). `extraKeyOrder` хранит порядок показа дополнительных клавиш в редакторе; на работу mapper он не влияет.

`holdModifiers` — клавиши слоя, у сочетания которых модификаторы остаются нажатыми до отпускания клавиши, удерживающей слой; основная клавиша нажимается и отпускается вместе с физической. Так работает переключение окон: в примере удержание `AltLeft` включает `desktop`, Tab выдаёт Alt+Tab, повторные Tab листают окна при всё ещё зажатом Alt, CapsLock (Alt+Shift+Tab) листает назад, а отпускание `AltLeft` отпускает Alt и выбирает окно. Модификаторы, которые не нужны следующей такой клавише, отпускаются (Shift после Alt+Shift+Tab → Alt+Tab), Alt остаётся. Каждая клавиша из списка должна иметь действие в `keys` (не `null`).

### Правила

| Поле | Смысл |
| --- | --- |
| `key` | физическая клавиша или сочетание клавиш-участников через `+` (обязательно) |
| `id` | идентификатор; если его нет, генерируется при загрузке |
| `enabled` | `false` — правило сохранено, но не работает |
| `when` | [условия](#условия-when) |
| `tap` | действие при нажатии; нет поля — сама клавиша, `null` — ничего |
| `doubleTap` | `{ "action", "timeoutMs"? }` — действие при двойном нажатии |
| `hold` | что делает удержание (см. ниже) |
| `longHold` | `{ "action", "timeoutMs"? }` — действие при долгом удержании; нельзя сочетать с `hold` |
| `tapDecision` | как решать нажатие/удержание для этого правила; по умолчанию `settings.timing.tapDecision` |

Правил с одной и той же клавишей может быть несколько: они проверяются по порядку в `rules`, и срабатывает первое, у которого выполнены условия `when`. Отключённые правила пропускаются.

Поля `hold`:

| Поле | Смысл |
| --- | --- |
| `layer` | слой, который действует, пока клавиша удерживается |
| `keys` | клавиша или сочетание, зажатые во время удержания (например `ControlLeft`). Нет поля — сама клавиша (или ничего, если задан `layer`), `null` — ничего |
| `timeoutMs` | через сколько нажатие считается удержанием; по умолчанию `settings.timing.holdMs` |

### Макросы и команды

У макроса обязателен `id` (см. [идентификаторы](#идентификаторы)); он может совпадать с ID встроенного макроса: пространства `macro:` и `builtin:` независимы. `steps` — список действий, включая `pause:<мс>`. `stepPauseMs` и `modifierDelayMs` переопределяют значения из `settings.timing` и сохраняются при вложенном вызове. Отсутствующее переопределение наследует глобальную настройку, а не настройку вызывающего макроса. Циклы запрещены; развёртывание ограничено 1000 элементами (включая ссылки) и глубиной вложенности 10. Явная последняя пауза также выполняется. Команды внутри макроса ожидаются до успешного завершения, а ошибки прерывают последовательность. Общий `settings.timing.macroTimeoutMs` включает все шаги и ожидания. См. [поведение макросов](features.md#макросы).

У команды обязателен `id`. `unix` — сценарий POSIX `sh` для Linux и macOS, `windows` — сценарий PowerShell. `workingDirectory` — каталог запуска: по умолчанию домашний, `~/…` и относительный путь отсчитываются от домашнего каталога, поэтому такие пути переносятся между компьютерами. Команды из раскладки выполняются только при `settings.commandsEnabled`.

### Страницы меню

`quickActionPages` и `emojiPages` — страницы меню быстрых действий и эмодзи. Ключи `cells` — клавиши сетки `KeyQ KeyW KeyE KeyR KeyT / KeyA KeyS KeyD KeyF KeyG / KeyZ KeyX KeyC KeyV KeyB`. Ячейка быстрого действия — строка с действием или объект `{ "name"?, "action" }`, ячейка эмодзи — вставляемый текст. Если списка страниц нет, приложение показывает одну пустую страницу.

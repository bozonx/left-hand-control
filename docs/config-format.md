# Формат config.json и файлов Keymap

Приложение хранит два вида файлов:

- `config.json` — постоянные настройки этого компьютера;
- `keymaps/<имя>.json` — Keymap библиотеки. Keymap переносима: её можно скопировать на другой компьютер.

Пути к каталогам описаны в [руководстве разработчика](development/guide.md). Оба файла редактируются только через приложение. Ручное редактирование не поддерживается: оно делается на страх и риск пользователя. Такие изменения в лучшем случае применяются после перезапуска и могут быть перезаписаны следующим сохранением, а ошибка в файле не даёт приложению загрузить его.

## Общие правила

- Каждый файл содержит поле `version` — версию формата файла (а не содержимого: авторская версия Keymap хранится в `meta.keymapVersion`). Версии `config.json` и Keymap независимы; сейчас оба формата имеют версию 1. Файл без версии не загружается. Если версия больше поддерживаемой, приложение сообщает, что файл создан более новой версией, и не загружает его.
- Чтение строгое: неизвестное поле, значение не того типа или неизвестное значение перечисления — ошибка с номером строки и столбца. Файл при этом не перезаписывается. Так приложение никогда не сохраняет файл, молча выбросив непонятые части.
- Необязательные поля можно не писать: берётся значение по умолчанию. Приложение не записывает пустые списки и значения по умолчанию. В `config.json` записываются только настройки, отличающиеся от значений по умолчанию, поэтому новая версия может изменить значение по умолчанию для всех, кто его не менял. Значения по умолчанию, от которых зависит поведение ввода (`settings.timing`), — часть контракта формата: они меняются только как заметное изменение поведения с записью в CHANGELOG.
- Стиль имён: поля — camelCase; значения перечислений — camelCase (`permissiveHold`, `libeiOnly`, `eInk`); сочетания клавиш — синтаксис действий (`Ctrl+Shift+KeyV`); языки — коды BCP 47 (`ru`, `zh-Hans`).
- Смысловые проблемы (ссылка на несуществующий макрос, неизвестная клавиша в действии) не мешают загрузке. Их показывает диагностика правил, а mapper не запускается с блокирующими ошибками.
- Политика совместимости. В версии 1 могут появляться только новые необязательные поля, новые значения перечислений и объектная форма у значения, которое сейчас записывается строкой (так уже устроены клавиши слоя и ячейки быстрых действий: строка или объект `{ "action", … }`); строковая форма при этом остаётся действительной, а смысл существующих полей не меняется. Любое другое изменение повышает `version`. Старая сборка не читает файл с полем или значением, которого она не знает: в ошибке она указывает, что файл, вероятно, создан более новой версией приложения, и не перезаписывает его. Keymap, сохранённый новой версией, может не открыться в старой, если в ней используются новые возможности.
- Строковые значения без объектной формы. Ячейка эмодзи и шаг макроса — только строки, клавиша правила (`rules[].key`) — строка или массив клавиш аккорда. Подпись у ячейки эмодзи, параметры у шага макроса и параметры у клавиши правила пока не планируются; когда они понадобятся, для этих значений появится объектная форма, как у клавиш слоя.
- Повышение версии. Когда версия формата повышается, новая сборка по-прежнему читает файлы прежних версий и переводит их в текущую. Приложение всегда записывает текущую версию; перед первой перезаписью файла прежней версии рядом сохраняется его копия `<файл>.v<версия>.bak` (например, `config.json.v1.bak`), а существующая копия не заменяется. Форматы без поля `version` не поддерживаются.

### Подсказки редактора

Оба формата принимают необязательное корневое поле `$schema` — строку с адресом
JSON Schema для редактора. Приложение сохраняет её при редактировании, но не
загружает схему из сети и не использует адрес для выбора формата: это определяет
только `version`. При отсутствии поля приложение его не добавляет;
`null` и значения других типов запрещены.

Схемы лежат в каталоге [`schemas/`](../schemas/) репозитория и доступны по постоянным адресам:

- `config.json`: `https://raw.githubusercontent.com/bozonx/tecloid/main/schemas/config.v1.schema.json`;
- Keymap: `https://raw.githubusercontent.com/bozonx/tecloid/main/schemas/keymap.v1.schema.json`.

Номер в имени файла — `version` формата: схема версии 1 меняется только по политике совместимости,
а новая версия формата получает новый файл. Схема — подсказка для редактора (поля, значения
перечислений, диапазоны таймингов, грамматика ID); строки действий и смысловые проверки она не
описывает, окончательно файл проверяет приложение. Схемы генерируются из кода читателей, и тест
`published_schemas_match_the_readers` не даёт им разойтись.

### Идентификаторы

`id` уникален внутри своей коллекции: слои, правила, макросы, команды, страницы
быстрых действий, страницы эмодзи, автоправила и процессы игрового режима.
Сравнение ID регистрозависимое. Разные коллекции могут использовать одинаковый `id`.
У всех этих ID одна грамматика: от 1 до 64 символов из латинских букв, цифр, `_` и `-`
(`[A-Za-z0-9_-]{1,64}`). Поэтому ID без экранирования стоят в строках действий
(`macro:<id>`, `cmd:<id>`). Дубликаты — ошибка загрузки, а не правило
«последний побеждает». У шагов макроса ID нет: в JSON шаги — просто строки.

ID Keymap библиотеки устроены иначе: `user:<имя файла без .json>`. Имя файла
задаёт пользователь, поэтому оно может содержать любые символы, допустимые в
имени файла (`user:Основная`). Префикс `user:` оставляет место для других
источников Keymap.

У правил, страниц, автоправил и процессов можно пропустить `id`: загрузчик
детерминированно создаёт его (`rule-1`, `quick-1`, `emoji-1`, `process-1`),
предварительно резервируя все явно заданные ID этой коллекции. При сохранении
созданные ID записываются в файл.

### Условия `when`

Правила Keymap и автоправила (`settings.keymaps.auto.rules`) используют один объект условий:

| Поле | Смысл |
| --- | --- |
| `gameMode` | `on` или `off` — состояние игрового режима |
| `keyboardLayouts` | короткие id системной раскладки клавиатуры, например `us`; подходит любая из списка |
| `windows` | шаблоны активного окна; подходит любой из списка |
| `excludeWindows` | шаблоны окон, при которых условие не выполняется; если активное окно определить нельзя, условие тоже не выполняется |

Должны выполняться все заданные условия; объект без условий подходит всегда.
Шаблон окна — id приложения или имя процесса целиком без учёта регистра (`org.telegram.desktop`,
`Game.exe`, `.exe` необязательно), с масками `*` и `?` (`steam_app_*`), либо
`title:<текст>` — заголовок окна содержит текст.

### Контракт таймингов

Все длительности — целые миллисекунды. Дробные, отрицательные и выходящие за
диапазон числовые поля отклоняются при загрузке и редактировании; молчаливого
ограничения значений сохранённого файла нет. Некорректное действие `pause:`
в загруженном макросе показывает смысловая диагностика; mapper с ним не запускается.

| Поля | Допустимый диапазон, мс |
| --- | --- |
| `settings.timing.holdMs`, `doubleTapMs`; `rules[].hold.timeoutMs`, `doubleTap.timeoutMs` | 50–1000 |
| `settings.timing.longHoldMs`; `rules[].longHold.timeoutMs` | 100–60000 |
| `settings.timing.chordMs` | 10–500 |
| `settings.timing.macroStepPauseMs`, `macroModifierDelayMs`; `macros[].stepPauseMs`, `modifierDelayMs` | 0–2000 |
| `pause:<мс>` в шагах макроса | 1–10000 |
| `settings.timing.macroTimeoutMs` | 1000–600000 |

Отсутствующий тайминг правила или макроса наследует соответствующую настройку
из `settings.timing`; при сохранении наследуемое поле опускается. Явный `null`
в таймингах запрещён везде. В действиях `null` по-прежнему означает «ничего не делать».
Ноль разрешён только для межшаговой задержки и задержки модификаторов: он
означает отсутствие дополнительной задержки. Ноль не означает наследование,
отключение распознавания жеста или неограниченное выполнение макроса.
`macroTimeoutMs` ограничивает выполнение макроса целиком; отдельная допустимая
пауза не отменяет этот предел. Hold и long hold — альтернативные режимы,
поэтому требования `longHoldMs > holdMs` нет.

### Диагностика содержимого

Перед запуском mapper проверяется весь активный Keymap: действия правил,
клавиши и действия слоёв, шаги и циклы вызовов макросов, действия быстрых меню,
условия окон и поддерживаемые сочетания параметров правил. Ошибка содержит
путь к элементу; для макроса указывается конкретный шаг. Некорректное действие
в слое или меню не пропускается молча. Диагностика не переписывает файл:
Keymap со смысловыми ошибками можно открыть и исправить в редакторе.


## Действия

Действие — строка:

| Вид | Пример |
| --- | --- |
| клавиша или сочетание (коды клавиш, основанные на W3C `KeyboardEvent.code`) | `KeyA`, `Ctrl+KeyC`, `Ctrl+Shift+ArrowLeft` |
| пользовательский макрос | `macro:myMacro` |
| встроенный макрос | `builtin:copyLineText` |
| команда | `cmd:<id>` |
| системное действие | `sys:switchToDesktop2`, `sys:showDesktop` |
| действие Tecloid | `tecloid:showQuickMenu1`, `tecloid:toggleGameMode` |
| глобальное сочетание KDE | `kde:kwin/Window Maximize` |
| действие установленного приложения (Linux, freedesktop `Actions=`) | `xdg:firefox/new-private-window` |
| ввод текста | `text:Привет` |
| пауза (только в макросах) | `pause:200` |

Строка вида `слово:…` с неизвестным префиксом из строчной латинской буквы и букв или цифр (например, действие из более новой версии) загружается и сохраняется без изменений, но диагностика сообщает о неизвестном типе действия, и mapper с ним не запускается.

Там, где действие необязательно, отсутствие поля значит «как у физической клавиши», а `null` — «ничего не делать». Пустая строка — ошибка.

Сочетание в действии записывается как модификаторы и основная клавиша через `+`: `Ctrl`, `Shift`, `Alt`, `Meta` обозначают левую клавишу модификатора, а коды с указанием стороны (`ControlRight`, `AltRight`) — конкретную. Каноническая форма — `Ctrl+Shift+KeyA`: сначала модификаторы в порядке `Ctrl`, `Alt`, `Shift`, `Meta`, затем основная клавиша, без пробелов. Читатель также принимает другой порядок модификаторов и полные имена (`ControlLeft` вместо `Ctrl`); строки действий при загрузке не нормализуются. Клавиша правила (`rules[].key`) записывается иначе: одна клавиша — строка (`"CapsLock"`), аккорд из нескольких одновременно нажатых клавиш — массив (`["ControlLeft", "KeyA"]`, не меньше двух элементов). Знак `+` внутри клавиши правила запрещён и вызывает ошибку загрузки: в строках действий он соединяет модификаторы с клавишей, а у аккорда другой смысл. Допустимы только физические коды клавиш; псевдонимы модификаторов `Ctrl`, `Shift`, `Alt`, `Meta` вызывают ошибку валидации.

Имена физических клавиш следуют W3C `KeyboardEvent.code`; для клавиш вне стандарта используются имена Chromium, а затем имена на основе Linux `KEY_*`. Поэтому каталог содержит расширения `WLAN`, `WWAN`, `UWB`, `VideoPrev`. Аббревиатуры сохраняют верхний регистр; `VideoPrev` и `MediaTrackPrevious` обозначают разные Linux-коды и не являются псевдонимами.

Встроенные макросы используют ссылки `builtin:<id>`, пользовательские — `macro:<id>`. Их ID могут совпадать: ссылки разрешаются независимо.

ID встроенных макросов начинаются с глагола: `goTo…` (перемещение курсора), `select…`, `copy…`, `cut…`, `paste…`, `replace…WithClipboard`, `insert…`, `duplicate…`. Объект называется одинаково во всех макросах: `Line` — строка целиком вместе с переводом строки, `LineText` — текст строки без перевода, `Word` — слово под курсором, `ToLineStart`/`ToLineEnd` — от курсора до начала или конца строки. Например: `builtin:goToNextLineEnd`, `builtin:goTo5LinesUp`, `builtin:copyLineText`, `builtin:cutLine`, `builtin:selectWord`, `builtin:insertEmptyLineAbove`.

Системные действия (`sys:`): `closeWindow`, `minimizeWindow`, `maximizeWindow`, `maximizeWindowVertically`, `toggleWindowKeepAbove`, `moveWindowToNextDesktop`, `moveWindowToPreviousDesktop`, `moveWindowToNextScreen`, `moveWindowToPreviousScreen`, `switchToNextDesktop`, `switchToPreviousDesktop`, `showDesktop`, `showOverview`, `showAppLauncher`, `turnOffScreen`, `lockSession` и нумерованные `switchToDesktopN`, `moveWindowToDesktopN`, `switchToKeyboardLayoutN` (N от 1 до 10). Поддержка по платформам — в [platforms.md](development/platforms.md). Имена следуют привычным названиям системных команд и не гарантируют одностороннюю установку состояния: на KDE `maximizeWindow`, `maximizeWindowVertically`, `showDesktop`, `showOverview` и `showAppLauncher` вызывают соответствующие системные переключатели. Повторный вызов может вернуть прежнее состояние; точное поведение определяет система.

Действия установленных приложений (`xdg:<desktop-id>/<action>`): `desktop-id` — имя файла `.desktop` без расширения (для файла из подкаталога `kde4/foo.desktop` — `kde4-foo`), `action` — идентификатор из его ключа `Actions=`. Приложения с `DBusActivatable=true` получают вызов `org.freedesktop.Application.ActivateAction`, остальные запускаются по `Exec` действия. Если приложение не установлено, действие пропускается с предупреждением. Только Linux.

Действия самого Tecloid (`tecloid:`): `showQuickMenuN`, `showEmojiMenuN`, `showQuickMenuRecent`, `showEmojiMenuRecent`, `showSettings`, `activateKeymapN`, `toggleGameMode`, `setGameModeAuto`, `setGameModeOn`, `setGameModeOff`. Имена действий начинаются с глагола.

`tecloid:showQuickMenuRecent` и `tecloid:showEmojiMenuRecent` открывают меню на странице, которая была открыта в нём последней; повторное нажатие листает страницы (их же вызывают встроенные сочетания Ctrl+Alt+F12 и Ctrl+Alt+F11).

Действия `tecloid:showQuickMenuN` и `tecloid:showEmojiMenuN` открывают страницу меню по её позиции (N от 1, без верхней границы; если страницы с таким номером нет, открывается последняя). `tecloid:activateKeymapN` (N от 1 до 5) включает Keymap по позиции в порядке библиотеки (`settings.keymaps.order`). Ссылка по позиции, а не по id, выбрана намеренно: клавиши назначаются на номера один раз, а что они открывают, меняется перестановкой страниц или Keymap, которую видно в интерфейсе. Перестановка и удаление страниц в редакторе эти действия не переписывают.

    "reduceMotion": "system",

    "layerHint": false,
    "locale": "auto",

      "keyboards": ["/dev/input/by-id/usb-Keyboard-event-kbd"],

### settings

| Поле | Значения | По умолчанию |
| --- | --- | --- |
| `experimental` | показывать в интерфейсе возможности, которые ещё в разработке (сейчас — управление игровым режимом); поведение ядра не меняется | `false` |
| `appearance` | `system`, `light`, `dark`, `eInk` | `system` |
| `highContrast`, `reduceMotion` | `system` — как в системе (на Linux — XDG Settings portal: `contrast`, `reduced-motion`; на KDE ещё нулевая скорость анимации), `on`, `off`. В версии 1 это были `true`/`false`: `true` читается как `on`, `false` — как `system` | `system` |
| `locale` | `auto`, `en`, `ru`, `de`, `fr`, `es`, `it`, `pt`, `pl`, `tr`, `uk`, `cs`, `hu`, `ro`, `el`, `hr`, `ka`, `kk`, `zh-Hans`, `zh-Hant`, `ja`, `ko` | `auto` |
| `devices.keyboards`, `devices.mice` | списки путей к устройствам ввода; в Linux — стабильная ссылка `/dev/input/by-id/…` или `/dev/input/by-path/…`, которая переживает перезагрузку и переподключение. Формат допускает несколько устройств, текущая версия поддерживает не больше одного устройства каждого вида; больший список — ошибка загрузки | пусто |
| `timing` | значения по умолчанию для правил и макросов, в миллисекундах; правило или макрос может задать своё | см. пример |
| `timing.tapDecision` | `permissiveHold` (нажатие другой клавиши фиксирует удержание только при вложенном отпускании или по таймауту; для клавиши, у которой удержание — только слой, клавиши вне этого слоя удержание не фиксируют), `holdOnOtherKeyPress` (сразу). Правило модификатора, который при удержании остаётся собой или становится другим модификатором (например, Meta с удержанием Ctrl), без своего `tapDecision` работает как `holdOnOtherKeyPress` | `permissiveHold` |
| `keymaps.mode` | `manual` — работает `keymaps.manualKeymap`; `auto` — первое подходящее правило `keymaps.auto.rules`, иначе `keymaps.auto.fallback` | `manual` |
| `keymaps.manualKeymap` | id Keymap ручного режима | нет |
| `keymaps.order` | порядок Keymap библиотеки (id); задаёт номера для `tecloid:activateKeymapN` и порядок списка. Keymap, которых нет в списке, идут после перечисленных | пусто |
| `keymaps.auto.rules[].keymap` | обязательно: id Keymap или явный `null` (нативный ввод без переназначений). Пустая строка — ошибка | — |
| `keymaps.auto.rules[].enabled` | `false` сохраняет правило, но не применяет его | `true` |
| `keymaps.auto.rules[].when` | [условия](#условия-when); правила проверяются по порядку, применяется первое подходящее | — |
| `keymaps.auto.fallback` | Keymap, когда ни одно правило не подошло; `null` — нативный ввод | `null` |
| `commandsEnabled` | разрешить действия `cmd:`; без этого команды из Keymap не выполняются | `false` |
| `gameMode.detectors` | источники автоопределения игр; каждая платформа использует только свои | зависит от ОС |
| `gameMode.foregroundOnly` | игры из `detectors` (лаунчеры, Game Bar) учитываются, только пока их окно активно; Steam в Windows не называет процесс игры и учитывается всегда | `true` |
| `gameMode.processes[]` | процесс-признак игры: `name` — шаблон процесса, `foregroundOnly` (по умолчанию `true`) — учитывать процесс, только пока его окно активно; с `"exclude": true` — процесс, который игровой режим не включает | — |
| `linux.textMode` | `libeiWithClipboardFallback` — набор через libei, а текст с символами, которых нет в раскладке, вставляется через буфер обмена; `libeiOnly` — только libei, такой текст пропускается; `keycode`, `clipboard`, `ydotool`, `xdotool`. В версии 1 `libeiWithClipboardFallback` назывался `libei`, а `libeiOnly` — `libeiPure` | `libeiWithClipboardFallback` |
| `linux.pasteShortcut` | сочетание вставки в синтаксисе действий. Порядок и написание модификаторов не важны (`Shift+Ctrl+KeyV` = `Ctrl+Shift+KeyV`). Текущая версия поддерживает `Shift+Insert`, `Ctrl+KeyV`, `Ctrl+Shift+KeyV`; другое сочетание — ошибка загрузки | `Shift+Insert` |
| `linux.terminalPasteShortcut` | сочетание вставки, когда получатель — терминал (Konsole, kitty, Alacritty, GNOME Terminal и др., определяется по классу окна); те же значения или `sameAsPaste` — как `pasteShortcut` | `Ctrl+Shift+KeyV` |
| `linux.ydotoolPath`, `linux.xdotoolPath` | путь к программе; без поля — поиск в `PATH`. Пустая строка — ошибка | нет |

Id Keymap библиотеки имеют вид `user:<имя файла без .json>`. При переименовании Keymap в приложении все ссылки в `config.json` обновляются.

Положение переключателя игрового режима хранится в `settings.gameMode.control` (`auto`, `on`, `off`; по умолчанию `auto`). Последний ручной выбор Keymap хранится в `settings.keymaps.manualKeymap`; автоматический выбор не записывается поверх него. Открытый редактор и страница интерфейса не восстанавливаются.


## Файл Keymap

Необязательный объект `meta` содержит необязательные строки `name`, `author`,
`keymapVersion` и `description`. `name` — переносимое авторское название, независимое
от имени файла; `author` — автор; `keymapVersion` — произвольная строка авторской
версии Keymap, не связанная с версией формата `version`; `description` — описание,
которое показывает и редактирует библиотека. Неизвестные поля, `null` и значения
других типов запрещены. Метаданные сохраняются при редактировании, копировании и
переименовании.

Имя файла остаётся локальным именем в библиотеке и основой ID `user:<имя>`.
Переименование файла или локальной копии не меняет авторское `meta.name`.
Метаданные не задают стабильный ID и не используются для поиска обновлений.
Редактор пока не предоставляет полей для изменения `meta.name`, `meta.author` и `meta.keymapVersion`.

### Слои

`id` обязателен, `name` по умолчанию равен `id` (совпадающее с `id` имя не записывается; так же у макросов и команд). В `keys` код клавиши указывает на действие; `null` глушит клавишу в слое, а клавиша, которой нет в `keys`, прозрачна: работает назначение нижнего активного слоя, а если его нет — правило базового слоя. Триггер другого слоя, прозрачный в текущем, включает свой слой поверх него. Вместо строки можно записать объект `{ "action", "holdModifiers"? }` — так задаются параметры клавиши; приложение пишет объект, только когда параметр отличается от значения по умолчанию. Клавиши записываются в порядке клавиатуры. `extraKeyOrder` хранит порядок показа дополнительных клавиш в редакторе; на работу mapper он не влияет.

`holdModifiers: true` — у сочетания клавиши слоя модификаторы остаются нажатыми до отпускания клавиши, удерживающей слой; основная клавиша нажимается и отпускается вместе с физической. Так работает переключение окон: в примере удержание `AltLeft` включает `desktop`, Tab выдаёт Alt+Tab, повторные Tab листают окна при всё ещё зажатом Alt, CapsLock (Alt+Shift+Tab) листает назад, а отпускание `AltLeft` отпускает Alt и выбирает окно. Модификаторы, которые не нужны следующей такой клавише, отпускаются (Shift после Alt+Shift+Tab → Alt+Tab), Alt остаётся.

### Правила

| Поле | Смысл |
| --- | --- |
| `key` | обязательно: код физической клавиши строкой или аккорд — массив из двух и более кодов |
| `id` | идентификатор; если его нет, генерируется при загрузке |
| `enabled` | `false` — правило сохранено, но не работает |
| `when` | [условия](#условия-when) |
| `tap` | действие при нажатии; нет поля — сама клавиша, `null` — ничего |
| `doubleTap` | `{ "action", "timeoutMs"? }` — действие при двойном нажатии |
| `hold` | что делает удержание (см. ниже) |
| `longHold` | `{ "action", "timeoutMs"? }` — действие при долгом удержании; нельзя сочетать с `hold` |
| `tapDecision` | как решать нажатие/удержание для этого правила; по умолчанию `settings.timing.tapDecision` |

Правил с одной и той же клавишей может быть несколько: они проверяются по порядку в `rules`, и срабатывает первое, у которого выполнены условия `when`. Отключённые правила пропускаются.

Сочетание срабатывает, только если все его клавиши, включая модификаторы, нажаты в пределах `settings.timing.chordMs`; модификатор, зажатый раньше, остаётся обычным модификатором. Если сочетание входит в более длинное, оно ждёт остальные клавиши до конца этого окна, поэтому длинное сочетание срабатывает при любом порядке нажатия. Сочетание из модификаторов без действия на нажатие, прерванное другой клавишей до долгого удержания, возвращает модификаторы как есть (аккорд `["ShiftLeft", "ControlRight"]`, затем X — это Ctrl+Shift+X). В слое сочетание работает, если слой не назначает ни одну из его клавиш.

Поля `hold`:

| Поле | Смысл |
| --- | --- |
| `layer` | слой, который действует, пока клавиша удерживается |
| `action` | клавиша или сочетание, зажатые во время удержания (например `ControlLeft`). Нет поля — сама клавиша (или ничего, если задан `layer`), `null` — ничего |
| `timeoutMs` | через сколько нажатие считается удержанием; по умолчанию `settings.timing.holdMs` |

### Макросы и команды

У макроса обязателен `id` (см. [идентификаторы](#идентификаторы)); он может совпадать с ID встроенного макроса: пространства `macro:` и `builtin:` независимы. `steps` — список действий, включая `pause:<мс>`. `stepPauseMs` и `modifierDelayMs` переопределяют значения из `settings.timing` и сохраняются при вложенном вызове. Отсутствующее переопределение наследует глобальную настройку, а не настройку вызывающего макроса. Циклы запрещены; развёртывание ограничено 1000 элементами (включая ссылки) и глубиной вложенности 10. Явная последняя пауза также выполняется. Команды внутри макроса ожидаются до успешного завершения, а ошибки прерывают последовательность. Общий `settings.timing.macroTimeoutMs` включает все шаги и ожидания. См. [поведение макросов](features.md#макросы).

У команды обязателен `id`. `sh` — сценарий POSIX `sh` для Linux и macOS, `powershell` — сценарий PowerShell для Windows. Пустой сценарий не записывается; команда без сценария для текущей ОС при срабатывании пропускается с предупреждением. `workingDirectory` — каталог запуска: по умолчанию домашний, `~/…` и относительный путь отсчитываются от домашнего каталога, поэтому такие пути переносятся между компьютерами. Команды из Keymap выполняются только при `settings.commandsEnabled`.

### Страницы меню

`quickMenuPages` и `emojiMenuPages` — страницы меню быстрых действий и эмодзи. Ключи `cells` — клавиши сетки `KeyQ KeyW KeyE KeyR KeyT / KeyA KeyS KeyD KeyF KeyG / KeyZ KeyX KeyC KeyV KeyB`. Ячейка быстрого действия — строка с действием или объект `{ "name"?, "action" }`, ячейка эмодзи — вставляемый текст (без подписи). Если списка страниц нет, приложение показывает одну пустую страницу.

Rule triggers also accept `Shift`, `Ctrl`, `Alt` and `Meta`, each matching either physical side. A trigger cannot contain overlapping generic and physical modifiers (for example `Ctrl+ControlLeft`). Physical triggers take priority over overlapping generic triggers; existing physical triggers keep their meaning. The optional `settings.copyOsd` boolean defaults to false and announces synthetic copy commands from Tecloid, without verifying clipboard contents.

# Проверка макросов

Поведение описано в [features.md](../features.md#макросы); форматы файлов не менялись.
Все сценарии используют временную конфигурацию. Не назначайте команды проверки
на настоящие устройства или рабочую раскладку.

## Автоматические регрессии

```sh
cargo test --locked -p lhc-core --lib macro
cargo test --locked -p slint-shell --lib pages::macros::tests
cargo run --locked -p slint-shell --example macros
cargo run --locked -p slint-shell --example small-window
```

Проверки ядра охватывают пределы развёртывания и вложенности, циклы, переименование
входящих ссылок и обмен ID, последнюю паузу и очередь, собственные задержки вложенных
макросов, ожидание команды, продолжение после успеха, прерывание после ошибки,
отмену при остановке и таймауте. Командные тесты Linux дополнительно проверяют
ошибку запуска, ненулевой код завершения и завершение группы процессов при отмене.
Тесты runner используют управляемые моменты времени и подставляют результат
команды, поэтому не зависят от скорости запуска shell.

Стенд страницы проверяет синхронизацию ссылок между черновиком, моделями UI и
документом после переименования, отказ удаления используемого макроса, ошибку
конкретного шага, сохранение неверного черновика, создание макроса при ошибках и
отбрасывание черновика. `small-window` проверяет страницу в минимальном окне, включая доступность кнопок добавления шага и паузы после вертикальной прокрутки.

## Визуальная проверка на KDE Wayland

- Введите неверную паузу: ошибка видна рядом с нужным шагом; черновик явно помечен
  как неприменённый. Исправьте значение и проверьте исчезновение ошибки.
- При ошибке одного макроса создайте другой; затем отбросьте черновик с подтверждением.
  Последняя применённая версия должна остаться в документе.
- Проверьте указания мест использования и запрет удаления используемого макроса.
- Проверьте светлую, тёмную, E-ink и высококонтрастную темы, русский язык,
  минимальный размер окна и клавиатурную навигацию, включая подтверждение отмены.
- При настоящем mapper e2e проверяйте ввод только в отдельном тестовом окне.
  Для ошибки команды, таймаута и переполнения очереди должно появляться уведомление.

Прохождение тестов движка не подтверждает доставку клавиш приложению, завершение
системного действия или работу Windows. Эти среды и действия отмечайте отдельно
в отчёте приёмки.

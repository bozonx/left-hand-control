  text-unicode.png shows the empty focused receiver and the same error in the UI.
The current clipboard backend requires Wayland data-control ownership, unavailable
in this tested GNOME session. ASCII/quick text can use the portal keyboard path;
Unicode here falls back to the safe clipboard path, which rejects unavailable
ownership. This is an app backend capability blocker, not missing consent.
No unsafe clipboard workaround or disabled destination validation was introduced.

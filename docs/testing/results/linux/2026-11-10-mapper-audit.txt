Mapper audit implementation — 2026-11-10

Environment: Linux, KDE Plasma, Wayland; /dev/uinput and /dev/input available.
Tests use synthetic devices and private runtime/config directories. No physical
user keyboard or mouse was grabbed for acceptance tests.

Audit decisions
1. Re-intercept the current press after hold-on-other replays its decision
   buffer. Keep a regression for an old release preceding a repeated press.
2. Nested releases and timeout use the first ordinary buffered key, including
   the inverse case (mapped first key, later unmapped key released).
3. Flow tap: 135 ms after an unmodified native letter, only permissive layer
   rules with a tap and without double-tap or long-hold. Modifier shortcuts,
   mouse clicks and other intervening presses interrupt that typing context.
4. Fetch nonblocking input after every wait, including poll timeout, before tick.
5. A second double-tap press resolves long-hold decisions and counts as layer use.
6. Layer significance considers active conditional rules and chords.
7. Keep intentional behavior: once typing resolves a held trigger as tap, its
   release is consumed; re-press it to activate the layer. Documented explicitly.
8. Capture the selected Linux mouse and relay via a separate virtual pointer.
   Preserve relative/absolute axes and properties. Route button codes, including
   BTN_TOUCH, to the pointer; emit modifier output before clicks. Preserve pointer
   frames, forward movement during macros, and exclude our pointer from discovery.
   Failed pointer setup leaves the physical mouse available and retries later;
   do not grab while a button is already held.

Timing: synchronous modifier-delay cap reduced from 50 to 15 ms. Macro timing
remains asynchronous. Default hold and double-tap windows remain 200 ms; the
suggested 150 ms double-tap default was optional in the audit. Double-tap delay
and flow-tap exclusions are documented in docs/features.md.

Limits
No UI source or translation changes; graphical page scenarios were not run.
Synthetic evdev/uinput tests verify output events and timestamps, not delivery
inside a real application or physical mouse hardware behavior. Natural typing,
physical mouse hotplug and device-specific behavior still need manual KDE
acceptance. Windows and macOS were not built or exercised. No dependencies,
persisted formats, IPC or CLI contracts changed.

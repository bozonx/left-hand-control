# Тестирование

Этот раздел отвечает на четыре вопроса: что проверяем, как повторить проверку,
какие результаты уже получены и какие области ещё не приняты.
Команды выполняются из корня репозитория. Наличие теста или зелёный CI не означает
полную приёмку платформы; `skipped` и не выполненные шаги не считаются пройденными.

## Окружения

| Система | Что проверяем сейчас | Инструкция |
| --- | --- | --- |
| Fedora 44 KDE, Wayland | Полный прогон RPM в VM 2026-10-21: 42 PASS, 0 FAIL | [Fedora KDE](fedora-kde.md) |
| Debian 13 KDE, Wayland | DEB: 42 PASS без SKIP, включая S3; стенд i440fx | [Debian KDE](debian-kde.md) |
| Kubuntu 26.04, Wayland | Полный прогон архива в VM 2026-10-21: 42 PASS, 0 FAIL | [Kubuntu](kubuntu-kde.md) |
| Ubuntu 26.04, GNOME Shell 50, Wayland | Отдельный VM smoke с расширением GNOME и portal; объём меньше KDE | [GNOME Wayland](gnome.md) |
| Windows 11 | Нативные тесты, debug smoke, release mapper и popup-сценарии в VM | [Windows](windows.md) |
| macOS | CI: компиляция, unit/integration, clippy, release check; desktop-приёмки нет | [macOS](macos.md) |
| Debian 12/13, Ubuntu 22.04/24.04, Fedora, openSUSE Tumbleweed, Arch | Установка/удаление пакетов в контейнерах; без рабочего стола | [Общие проверки и CI](common.md#пакеты-и-контейнеры) |

Sway, Hyprland, другие версии GNOME и X11 не включены в текущую desktop-матрицу.
Поддержка протокола или код backend не являются свидетельством пройденного e2e.
Запланированные стенды в чек-листах также не считаются протестированными системами.

## Порядок работы

1. Выполнить [общие проверки](common.md) для изменённого кода.
2. По документу нужной среды запустить UI/mapper/VM-сценарии, которых касается изменение.
3. Для выпуска дополнить автоматические проверки [ручной приёмкой](manual-acceptance.md).
4. Записать команду, исходники, окружение, результаты и пропуски по
   [правилам хранения результатов](results/README.md).

[Руководство разработчика](../development/guide.md#4-e2e-проверки) содержит подробную
подготовку VM, пакетов и инструментов. [Матрица возможностей](../development/platforms.md)
описывает реализованные backend, а документы здесь — объём их проверки.

## Результаты

В Git сохраняем небольшие отчёты значимой приёмки, на которые ссылается документация
или решение о выпуске. Полные логи, снимки, метрики, образы VM и повседневные
диагностические попытки храним локально либо в артефактах CI.
История в [results/](results/README.md) относится к указанным в отчётах исходникам,
а не автоматически к текущему HEAD.

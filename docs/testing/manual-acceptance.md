# Ручная приёмка (L5)

Чек-лист ручной проверки продукта на реальном оборудовании: перехват и возврат ввода, раскладки, `text:`, правила, слои, макросы, условия, команды, системные действия, игровой режим и оболочка на Windows. Автоматические уровни (L0–L4) и порядок их запуска описаны в [руководстве разработчика](../development/guide.md#e2e-проверки); здесь — только то, что автоматикой не покрыто или требует физического железа.

Для ручных проверок используйте debug-сборку с отдельным `LHC_DEV_DIR` или установленный пакет на тестовой машине; личный конфиг не трогайте.

## 1. Предварительные условия

- Linux mapper реализован через evdev/uinput, Windows — через session-wide hooks и `SendInput` поверх общего движка. Windows ещё не прошла полную приёмку; macOS interception не реализован.
- На Windows раскладка определяется по foreground window. Возможности остальных окружений перечислены в [матрице платформ](../development/platforms.md).
- Для каждой среды отдельно фиксировать версию ОС, desktop/compositor, session type, список системных раскладок, физическую клавиатуру, разрешения и способ ввода текста.
- Сначала выполнять короткий smoke-набор. Полную матрицу запускать перед выпуском либо после изменения соответствующего платформенного backend'а.
- VM подтверждает функциональную совместимость. Hotplug, sleep/wake, несколько мониторов, физические media/mouse keys и особенности драйверов окончательно проверяются на реальном оборудовании.

## 2. Стенды

X11-сессии не поддерживаются и не проверяются (см. [platforms.md](../development/platforms.md)).

| Среда | Минимальный стенд | Финальный стенд |
| --- | --- | --- |
| KDE Wayland | текущая физическая система | текущая физическая система |
| GNOME Wayland | Fedora Workstation в KVM/QEMU | физическая сессия перед выпуском |
| Hyprland + waybar | Arch/Manjaro в KVM/QEMU | физическая сессия перед выпуском |
| Windows | Windows 11 в KVM/QEMU | физический Windows-компьютер перед выпуском |
| macOS | физический Mac | физический Mac |

В Linux VM использовать виртуальную клавиатуру как обычное evdev-устройство и предоставить доступ к `/dev/uinput`. Замеры задержки и памяти из VM не сравнивать с результатами физического KDE-стенда.

## 3. Общий smoke-набор для каждой среды

После появления рабочего backend'а среда должна пройти один и тот же короткий сценарий:

1. Запустить mapper, выбрать устройство и проверить native passthrough.
2. Выполнить простой remap `KeyA -> KeyB` и chord `KeyC -> Ctrl+KeyC` либо платформенный эквивалент.
3. Проверить tap, hold-модификатор, double tap и один слой.
4. Выполнить `text:Hello, мир! 🙂` при системных раскладках US и RU.
5. Выполнить макрос из chord, паузы и `text:`.
6. Переключить системную раскладку средствами ОС и получить обновлённое состояние в приложении.
7. Проверить одно условие по раскладке и одно условие по активному приложению.
8. Включить команды в настройках и выполнить по одному системному действию и команде.
9. Остановить mapper и убедиться, что клавиатура работает нативно и нет залипших клавиш.

Smoke-набор выполнять в нативном текстовом редакторе и дополнительно по одному разу в браузере, терминале и IDE для `text:`, макроса и возврата фокуса.

## 4. Перехват, passthrough и выдача клавиш

- [ ] Обычная печать без активных правил не меняется и не дублируется.
- [ ] Key-down, key-up и автоповтор сохраняют правильный порядок.
- [ ] Одновременные нажатия и быстрое перекрытие клавиш не теряются.
- [ ] Левые и правые Ctrl, Shift, Alt/Option и Meta/Super/Command различаются там, где это поддерживает ОС.
- [ ] Caps Lock и Num Lock работают, состояние и аппаратные индикаторы не расходятся.
- [ ] Проверены функциональные, навигационные, numpad и media keys.
- [ ] Дополнительные кнопки мыши участвуют в правилах без нарушения обычных кликов.
- [ ] Две клавиатуры и выбранная клавиатура ведут себя предсказуемо.
- [ ] Отключение и повторное подключение устройства не создаёт busy-loop и не оставляет grab.
- [ ] Остановка или аварийное завершение mapper не оставляет зажатых виртуальных клавиш.

## 5. Remap, tap/hold и слои

### Remap

- [ ] Одна физическая клавиша преобразуется в другую.
- [ ] Клавиша преобразуется в chord с одним и несколькими модификаторами.
- [ ] Modifier преобразуется в modifier с корректным удержанием и отпусканием.
- [ ] Native, transparent и swallow различаются согласно конфигурации.
- [ ] Физический key code правила не меняется при переключении языка ОС.
- [ ] Повтор remapped-клавиши не ускоряется и не дублируется неожиданно.

### Tap/hold/double tap

- [ ] Tap с отпусканием до timeout.
- [ ] Hold по timeout и hold при вложенном нажатии.
- [ ] Double tap внутри и вне заданного окна.
- [ ] `permissiveHold` на быстрых rolling-последовательностях с разным порядком отпускания.
- [ ] `holdOnOtherKeyPress` при тех же последовательностях.
- [ ] Native, swallow и action проверены отдельно для tap и hold.
- [ ] Индивидуальные timeout переопределяют глобальные значения.

### Слои

- [ ] Вход и выход из одного слоя.
- [ ] Стек двух слоёв и две клавиши, активирующие один слой.
- [ ] Action, transparent и swallow внутри слоя.
- [ ] `isolate` и `holdFor` с корректным временным снятием/добавлением модификатора.
- [ ] Слой одновременно с hold-модификатором.
- [ ] Необычный порядок отпускания физических клавиш.
- [ ] Обновление конфигурации и открытие/закрытие попапа при активном слое не оставляют состояние зависшим.

## 6. Literal text (`text:`)

Минимальный корпус:

```text
Hello, world!
Привет, мир!
aA zZ 0 9
!@#$%^&*()_+
[]{}();:'"\,./<>?
ёЁ №
á é ñ ö
🙂 👍🏽 👨‍💻
é
строка 1
строка 2
```

`é` проверить как готовый Unicode-символ и как combining sequence.

- [ ] Корпус вводится при системных раскладках US и RU.
- [ ] Проверены Caps Lock и удерживаемые перед запуском Shift, Ctrl, Alt/Option и Meta/Command.
- [ ] Символы появляются ровно один раз, в правильном порядке и независимо от раскладки, если это заявленная семантика `text:`.
- [ ] Проверены однострочное и многострочное поля, браузер, нативный редактор, терминал и IDE.
- [ ] Проверены emoji, variation selectors, skin tone и составная emoji-последовательность.
- [ ] Clipboard fallback сохраняет прежний текстовый clipboard и не восстанавливает его до обработки Paste.
- [ ] Определено и проверено поведение для нетекстовых MIME-типов clipboard.
- [ ] При смене активного окна текст не доставляется в постороннее приложение.
- [ ] Отказ portal/Accessibility и отсутствие вспомогательной программы дают видимую ошибку, а не молчаливую потерю текста.
- [ ] Первая выдача разрешения, повторный вызов, перезапуск приложения и отзыв разрешения обработаны предсказуемо.
- [ ] IME проверен хотя бы с одним composition-сценарием на каждой целевой ОС.

На Linux Wayland обязательны основной `libei`, его clipboard fallback и отдельный принудительный `clipboard`-проход. `keycode`, `libei-pure`, `ydotool` и `xdotool` проверять в тех окружениях, где они заявлены пользователю.

## 7. Макросы

- [ ] Последовательность обычных клавиш выполняется в заданном порядке.
- [ ] Chord с одним и несколькими модификаторами выполняется без залипания.
- [ ] Работают `pause:`, `text:`, `sys:`, `app:` и `cmd:` внутри макроса.
- [ ] Глобальные и индивидуальные `stepPauseMs` и `modifierDelayMs` применяются правильно.
- [ ] Удерживаемый пользователем modifier не отпускается макросом раньше времени.
- [ ] Повторный запуск во время выполнения имеет определённую семантику и не смешивает шаги.
- [ ] Ошибка, смена окна, остановка приложения и превышение лимита шагов освобождают все синтетические клавиши.
- [ ] Длинный макрос не блокирует input loop и UI.
- [ ] Встроенные и пользовательские макросы с одинаковым id разрешаются согласно правилам приоритета.

Для macOS до проверки определить переносимую семантику primary modifier и Home/End. Встроенные макросы с Windows/Linux-сочетаниями `Ctrl+C/V/X` нельзя считать кроссплатформенными без преобразования в Command или платформенных вариантов.

## 8. Системные раскладки и автоматический выбор layout

- [ ] Получение списка системных раскладок.
- [ ] Определение текущей раскладки и variant.
- [ ] Переключение из приложения и системными средствами.
- [ ] Событие `layout-changed` приходит один раз с актуальными данными.
- [ ] Быстрая серия US -> RU -> US не оставляет устаревший cache.
- [ ] Изменение списка раскладок, выход из сна и новая пользовательская сессия обновляют состояние.
- [ ] Неизвестная/неподдерживаемая раскладка не активирует неверный пользовательский layout.
- [ ] Manual mode сохраняет явно выбранный layout.
- [ ] Auto mode соблюдает `layoutOrder` и выбирает первый подходящий layout.
- [ ] Whitelist и blacklist системной раскладки работают, blacklist имеет приоритет.
- [ ] Условия по title, app id/process и активному окну обновляются при переключении приложений.
- [ ] При отсутствии совпадения mapper работает как полный native passthrough.
- [ ] Game Mode и fullscreen-условия проверены отдельно и вместе с layout/app conditions.

## 9. Системные и app-действия

Для минимального прохода на каждой ОС/DE выбрать по одному представителю каждой доступной группы:

- [ ] переключение рабочего стола;
- [ ] переключение системной раскладки;
- [ ] громкость или media action;
- [ ] закрытие, максимизация или перемещение окна;
- [ ] launcher или clipboard history;
- [ ] открытие Quick Menu и Emoji Menu;
- [ ] неподдерживаемое действие возвращает понятную ошибку и не выполняет другое действие.

Перед выпуском пройти весь заявленный каталог отдельно для KDE Wayland, GNOME, Hyprland, Windows и macOS. Недоступные для среды действия должны быть скрыты, помечены или явно отклонены.

## 10. Команды (`cmd:`)

- [ ] Выбирается платформенное поле `linux`, `windows` или `macos`.
- [ ] Аргументы, пробелы, кавычки и Unicode передаются предсказуемо.
- [ ] Проверены отсутствующий executable, ненулевой exit code и долгая команда.
- [ ] Команды выполняются вне input/UI loop.
- [ ] При выключенном переключателе команды не запускаются, включая шаги макросов.
- [ ] При выключенном переключателе категория команд скрыта в модале действий.
- [ ] Настройки показывают используемые команды и места назначений во всех раскладках.
- [ ] Несколько быстрых запусков не зависают.
- [ ] Поведение команд, которым нужен shell, отделено от прямого запуска программы.

## 11. Жизненный цикл и восстановление

- [ ] Старт, stop/start mapper и применение новой конфигурации без перезапуска приложения.
- [ ] Logout/login, lock/unlock и sleep/wake.
- [ ] Перезапуск compositor/Explorer/Finder и portal/backend, где это возможно.
- [ ] Смена устройства, отключение мыши/клавиатуры и восстановление после ошибки доступа.
- [ ] Отказ и повторная выдача input/Accessibility/portal-разрешений.
- [ ] Длительная работа, повторные макросы, слои и `text:` без роста памяти и CPU в простое.
- [ ] Обновление и удаление приложения не оставляет привилегированные службы, правила или автозапуск.

## 12. Когда проходить

- Перед мажорным релизом — полная матрица на заявленных средах (сейчас KDE Plasma 6 Wayland); для критических сценариев по 20 успешных повторов подряд.
- После изменения платформенного backend'а — smoke-набор раздела 3 и разделы, которые backend затрагивает.
- Перед заявлением поддержки новой среды — smoke-набор раздела 3 без потери ввода и залипших клавиш, основной Unicode-корпус `text:`, tap/hold, один слой, смешанный макрос и auto layout; все нужные разрешения воспроизводимы после чистой установки.

## 13. Игровой режим

Автоматические регрессии перечислены в руководстве разработчика. Вручную:

| Среда | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| KDE Wayland | Запуск/выход из оконной и borderless игры; Alt+Tab | Правильный источник; краткий разрыв удерживает Auto до 3 секунд |
| KDE Wayland, Spell | Горячая клавиша при запуске worker, затем On | Отложенный попап не открывается, включая повторный запуск worker |
| Linux | Игра Steam, Heroic/umu и Wine; белый/чёрный список | Источники переключаются независимо; исключение выигрывает в Auto |
| Linux | Отключение и восстановление GameMode/D-Bus на тестовой сессии | Недоступность отличается от отсутствия игры; после восстановления источник работает |
| Linux | Изменение `Categories` и `StartupWMClass` открытого приложения | Перечитывание индекса без перезапуска LHC, в покое не позднее следующей проверки через 30 секунд |
| Windows/macOS | On, затем Ctrl+Alt+F11/F12 в приложении-приёмнике | Системная регистрация освобождена; сочетание доступно приложению; после Off попапы снова работают |
| Windows | Steam отсутствует, `RunningAppID=0`, игра запущена; отказ чтения реестра | Различаются недоступный источник, отсутствие игры и активная игра |
| Windows | Игра/рабочий стол/панель задач, несколько мониторов | Полноэкранность относится к тому же окну, что app/process; оболочка не считается игрой |
| macOS | Игра из категории Games, затем настройки LHC | Категория относится к сохранённому приложению |
| macOS | CLI-процесс текущего и другого пользователя | В списке и фоновых правилах только процессы текущего пользователя |
| macOS | Два окна одного приложения на разных мониторах | Заднее fullscreen-окно не превращает переднее обычное окно в игровое |
| macOS | Safari, QuickTime, Keynote, PowerPoint fullscreen | Встроенный список исключает ложное включение |

## 14. Оболочка на Windows

Mapper на Windows реализован. `run-windows.py` проверяет оболочку и именованные mapper-сценарии через QEMU-клавиатуру (см. [матрицу приёмки](../development/windows-mapper.md)); стенд описан в [windows.md](windows.md). Вручную, один проход на каждый масштаб DPI:

- [ ] Tray открывает Settings, Emoji и Quick; переключатель mapper не зависает; Quit завершает процесс и не оставляет иконку в трее.
- [ ] Выбор в попапе, открытом из трея, не выполняет автоматическую вставку.
- [ ] Settings, Emoji и Quick открываются без дубликатов и невидимой ловушки фокуса.
- [ ] На 100%, 125% и 150% окна не обрезаны, области клика совпадают с отрисовкой, модальные окна, выпадающие списки и попапы видимы.
- [ ] Попап находится в рабочей области текущего монитора и не создаёт кнопку на панели задач.
- [ ] Тёмная/светлая тема и ru/en меняются без перезапуска процесса и без критического обрезания.
- [ ] Каталог из 1500 валидных emoji прокручивается и остаётся управляемым.
- [ ] `winit-skia` цветно рисует `☕`, `😀` и `👩‍💻`; прозрачность и скругления без артефактов.
- [ ] Первая активация Ctrl+Alt+F11/F12 из Notepad: попап открывается, Enter вставляет выбранное ровно один раз (сверка через `windows-receiver.ps1`), Esc и потеря фокуса ничего не вставляют.

Отдельная приёмка: полный каталог системных действий и получателей (Windows Terminal, браузеры), установщик/обновление, fullscreen, hot-plug мониторов, lock/unlock, sleep/wake, длительная нагрузка и физические клавиатуры. Аварийное завершение с удержанным виртуальным modifier не покрывается штатным stop и остаётся открытым ограничением. Unicode-ввод Windows использует `SendInput`, поэтому проверка сохранения нетекстовых форматов буфера относится к путям, использующим clipboard.

## 15. Формат отчёта

Для каждого стенда записывать:

1. ОС, desktop/compositor, X11/Wayland, версии portal/backend и архитектуру CPU.
2. Физическое или виртуальное окружение, тип input-устройства и выданные разрешения.
3. Версию приложения, commit и используемый text backend.
4. Результаты по разделам: пройдено / сбой / не поддерживается / не проверено.
5. Точный вход, ожидаемый и фактический результат для каждого сбоя.
6. Наличие потерянных событий, дубликатов и залипших модификаторов.
7. Логи и короткую запись экрана для проблем focus/input/lifecycle.

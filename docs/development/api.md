# Контракты shell, core и IPC

Slint shell вызывает Rust API `lhc-core` в своём процессе. Ядро не зависит от
Slint. IPC используется CLI-клиентом и отдельным Spell popup worker.

## Команды

`command::Command` — совместимое представление команды на границе CLI/IPC.
`ShellCommand` и `WorkerCommand` — отдельные наборы команд исполнителей.
Преобразование через `TryFrom` отклоняет неподходящего адресата; worker принимает
`Show(Popup)`, поэтому показать settings через него невозможно.

Существующий протокол сохранён: одна JSON-строка с текстовой командой,
ответ `queued` или `error: …`. `queued` подтверждает постановку в очередь
адресата, а не выполнение. `Dispatch` возвращает ошибку, если очередь UI
недоступна. Ошибки самого действия доставляются через события и уведомления.
`source` — метаданные происхождения для фокуса и game-mode, не авторизация;
Windows `auth` и Wayland activation `token` имеют разные назначения.

Settings отправляет команды worker через ограниченную FIFO-очередь, не ожидая
сокет на UI-потоке. Один фоновый отправитель сохраняет порядок конфигурации,
оформления и показа. При ошибке обмена он останавливается и сообщает shell;
последующие команды не выполняются на потенциально устаревшей конфигурации.
Новый worker получает отдельное имя сокета и актуальную конфигурацию.
Переполнение очереди возвращает ошибку отправителю. Завершение worker тоже
не ожидает сокет или процесс на UI-потоке.

## Конфигурация

`ConfigDocument::runtime_config()` создаёт `RuntimeConfig` с типизированным
`MapperConfig`. Проекция из модели редактора выполняется без JSON; lifecycle
API mapper принимает этот тип и валидирует его перед передачей backend.
JSON разбирается только на внешних границах, например в диагностическом стенде.
`current_config()` возвращает последнюю принятую mapper-конфигурацию;
обновление означает принятие управляющим каналом, а не синхронное выполнение.

Shell меняет документ через `Document`. `Document::edit()` вызывает
`ConfigDocument::transaction()`: изменения layout и settings готовятся на копии,
settings сохраняются после успешного callback. Ошибка callback оставляет память,
файл настроек и настройки game-mode прежними. Ошибка сохранения не коммитит копию.
Прямые файловые побочные эффекты через `paths()` внутри callback запрещены.

Для файлов библиотеки есть `Document::edit_library()`: callback выполняет одну
операцию ядра с собственным откатом файлов. Несколько fallible операций в таком
callback не объединяют: составные операции реализуются в ядре, например
`create_and_select_library_layout()`. Библиотечные записи и refresh autostart
отклоняются внутри обычной транзакции. Синхронизация autostart проходит через
отдельный метод `Document::sync_autostart()`.

После успешного изменения shell обновляет ревизию, передаёт конфигурацию mapper
и уведомляет зависимые представления. `Saved<T>` различает применённое изменение
и ошибку синхронизации mapper. Повторный вход из слушателей не держит borrow.

## События

`CoreEvent::AppAction(AppAction)` содержит типизированный запрос приложения.
Имена из конфигурации разбираются в `profile::app_action`, без промежуточных
строк вида `show_quick_menu_1`. Номер страницы/слота в `AppAction` ненулевой.
`CommandLaunchResult` сообщает результат запуска процесса; завершение процесса
и его exit status этим событием не обещаются.

Каждый подписчик имеет собственную очередь и поток. Уведомления состояния
(layout, game-mode, активное окно, held layer, доступность устройств) объединяются:
старое ожидающее уведомление того же типа заменяется новым в конце очереди.
Действия приложения, результаты и ошибки сохраняются в порядке поступления,
без отбрасывания по лимиту. Такая надёжная часть очереди не ограничена: постоянный
избыток действий у медленного подписчика требует памяти. Producer не ждёт UI.

Shell держит не более одного callback core в очереди UI: поток подписки ждёт
завершения обработки, пока в core объединяются новые уведомления состояния.
Это ожидание не блокирует producer или других подписчиков. Состояние при
обработке перечитывается из актуального snapshot там, где это необходимо.
Подписка не воспроизводит начальный snapshot: shell читает его при запуске.
